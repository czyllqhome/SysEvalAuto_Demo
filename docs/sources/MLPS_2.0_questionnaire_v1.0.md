# 网络安全等级保护 2.0：自动化定级信息收集问卷与规则设计（V1.0）

> 文档版本：V1.0 ｜ 更新日期：2026-11-03  
> 适用范围：中华人民共和国境内拟开展网络安全等级保护定级的**非涉密**信息系统。云计算平台、通信网络设施、数据资源等特殊对象需要启用相应规则。  
> 使用场景：系统负责人填报 → 规则引擎生成**初步建议等级** → 专家/主管部门（适用时）及备案审核 → 最终等级。  
> **重要免责声明**：本问卷是技术实现方案，不等同于官方定级报告；阈值预警、内部审核等级、风险标签不得被描述为国家标准规定的等保最低等级。

## 0. 设计原则及规则类型

**核心结论：等保定级不是将公网、用户数、个人信息数量等题目的“分数”直接累加。**《GB/T 22240-2020》的直接定级要素是：①受侵害客体；②对该客体的侵害程度。业务信息安全和系统服务安全须分别分析，最后取较高等级。

| 标识 | 类型 | 含义 | 是否直接改变国家标准矩阵计算结果 |
|---|---|---|---|
| **D** | Direct / 直接定级输入 | 受侵害客体 + 损害程度，用于国标矩阵计算 | **是** |
| **P** | Principle / 标准原则校验 | 特殊对象的标准适用原则，如承载平台、特定大数据平台 | **满足适用条件并经确认后** |
| **R** | Regulatory / 行业或监管要求 | 另有明确且适用的行业要求，须登记规范来源、版本、适用条件 | **经过核验后，可作为附加约束** |
| **T** | Trigger / 风险预警 | 公网暴露、个人信息规模、敏感信息等，触发更严格审查 | **否** |
| **E** | Evidence / 影响评估佐证 | 业务范围、停机、财务损失、用户规模、系统依赖等 | **间接支持 D 项判断，不直接计分** |
| **M** | Metadata / 元数据 | 责任主体、联系人、部署形式、架构等 | **否** |

**数据类型约定**：`text` 文本；`long_text` 长文本；`enum` 单选；`multi_enum` 多选；`integer` 非负整数；`decimal` 非负数；`boolean_3` 是/否/不确定；`file` 附件；`date` 日期。不得将“未填写/不确定”自动解释为“否”或“零损害”。

**题目通用字段**：`question_id`、`field_key`、`type`、`required`、`visible_if`、`evidence_refs`、`rule_type`。每个题目的 `field_key` 必须稳定，供 API、数据库、规则引擎和定级报告复用。

**条件逻辑**：B09 仅在支撑型对象出现；B10 在特殊对象出现。仅填写“某一台服务器、交换机、终端”时，提示“可能不是独立定级对象”，要求人工审查划分。  
**公网提示**：B06 触发风险审核及安全控制建议，**不自动把国家标准定级结果设置为二级**。

## F. 核心定级影响问卷（直接计分）

以下为**唯一直接进入 GB/T 22240-2020 矩阵计算的主要题组**。每个维度都要分别判断 **合法权益、社会秩序/公共利益、国家安全** 三类客体是否会受到侵害，以及损害程度。

### F.1 事故场景（佐证，不直接计分）

| 题号 / field_key | 问题 | 回答方式 | 类型 |
|---|---|---|---|
| F01 `scenario_disclosure` | 假设本系统最重要的数据遭到非法获取或泄露，最合理且可信的严重后果是什么？ | long_text：涉及的数据、人数、业务/法律/社会后果、判断依据 | E |
| F02 `scenario_tamper` | 假设关键业务数据或指令遭到篡改，最合理且可信的严重后果是什么？ | long_text | E |
| F03 `scenario_loss` | 假设关键业务信息丢失或被破坏，最合理且可信的严重后果是什么？ | long_text | E |
| F04 `scenario_unavailable` | 假设核心服务中断且无法在可容忍时间内恢复，最合理且可信的严重后果是什么？ | long_text；包含上下游依赖 | E |
| F05 `impact_evidence` | 对上述后果有哪些佐证材料？ | file/链接：BIA、数据资产清单、用户统计、业务流程、事故分析、法规、架构等 | E |
| F06 `scenario_confidence` | 对影响判断的把握程度？ | enum：有充分证据、基于负责人估计、信息不足 | E/QA |

### F.2 统一损害程度选项

> 以下六道题均采用相同选项，**每道题必须单选**：
>
> - `0` = 不会侵害该类客体（必须给出简要理由）；
> - `1` = **一般损害**：职能/业务能力局部下降，主要功能基本能够执行；损失较低，影响有限；
> - `2` = **严重损害**：职能/业务能力显著下降，主要功能受到严重影响；较高损失，较广影响；
> - `3` = **特别严重损害**：业务严重下降或主要功能无法执行；极高损失或大范围、极严重后果；
> - `9` = **无法判断**（中止自动最终建议并提交人工复核）。
>
> **注意**：0和9是自动化问卷的扩展编码，不是GB/T标准中的正式侵害程度。1、2、3的定性描述应结合受侵害客体和行业特点校准。`1/2/3` 是**损害程度编码**，**不是等保等级，也不能跨题简单求和**。

| 题号 / field_key | 需要回答的实际问题 | 选项 | 规则类型 |
|---|---|---|---|
| **F07** `info_rights_severity` | 业务信息被泄露、篡改、丢失或损坏，是否侵害**公民、法人和其他组织合法权益**？最严重程度如何？ | `0/1/2/3/9` + 原因 | **D** |
| **F08** `info_public_severity` | 业务信息遭破坏，是否侵害**社会秩序或公共利益**？最严重程度如何？ | `0/1/2/3/9` + 原因 | **D** |
| **F09** `info_national_severity` | 业务信息遭破坏，是否危害**国家安全**？最严重程度如何？ | `0/1/2/3/9` + 原因 | **D** |
| **F10** `service_rights_severity` | 核心服务不可用、失效或受扰，是否侵害**公民、法人和其他组织合法权益**？最严重程度如何？ | `0/1/2/3/9` + 原因 | **D** |
| **F11** `service_public_severity` | 核心服务失效，是否侵害**社会秩序或公共利益**？最严重程度如何？ | `0/1/2/3/9` + 原因 | **D** |
| **F12** `service_national_severity` | 核心服务失效，是否危害**国家安全**？最严重程度如何？ | `0/1/2/3/9` + 原因 | **D** |

### F.3 辅助说明（可按题目的 `severity` 动态弹出）

- **合法权益**：客户或员工权益受损、合同纠纷、经济损失、个人信息隐私侵害等。仅出现数据泄露**不自动**等于“严重损害”，应评估实际影响。
- **社会秩序/公共利益**：公众服务、医疗卫生秩序、公共交通、公共设施、群体性生产经营秩序等受到影响；**“服务面向公众”不等于“必然侵害公共利益”**，需要说明外溢性及受影响范围。
- **国家安全**：对国家安全事项形成现实且合理的危害情景。不得仅因系统有政府客户或位于某一行业就自动勾选。
- 如 F08/F09/F11/F12 选择 1–3，必须追加填写：受影响对象、可能事件链、覆盖地区、人数/规模、法律或业务依据，并触发人工专业复核。
- 建议默认评估**有现实依据的重大事故情景**，避免把不可信的极端假设当成定级依据；现有 WAF、备份、MFA 等安全控制不能直接改变受侵害客体类别。

## G. 行业适用规则、特殊对象及复核信息

| 题号 / field_key | 问题 | 回答方式 | 规则类型 |

# 第二部分：自动化定级算法与评分机制

## 1. 国家标准核心定级矩阵（适用于 D 类）

依据 GB/T 22240-2020 的**表1、表2与表3**：

| 受侵害客体 (`object`) | 损害程度=1 一般 | 损害程度=2 严重 | 损害程度=3 特别严重 |
|---|---:|---:|---:|
| `rights` = 公民、法人和其他组织合法权益 | **1** | **2** | **2** |
| `public` = 社会秩序、公共利益 | **2** | **3** | **4** |
| `national` = 国家安全 | **3** | **4** | **5** |

**易错提醒：合法权益 × 特别严重损害 = 2级，不是3级。**

计算方式：

1. 将 F07–F09 分别按照 `rights/public/national` 映射至矩阵，取最大值，得到 `business_information_level`。
2. 将 F10–F12 分别映射至矩阵，取最大值，得到 `system_service_level`。
3. `base_level = max(business_information_level, system_service_level)`。
4. 判断特殊对象适用的**标准原则 P**（例如已确认支撑平台承载其他系统的等级），以及**已核验且适用的行业规则 R**；需要保留法律性质、原文及条件，不得把预警规则混入其中。
5. 形成 `proposed_level`；若有关键未填、无法判断、未确认的原则/监管条件，状态设为 `pending_review`，不要作为最终结果。
6. 初步等级为二级及以上，按照标准要求由相应主体组织专家评审；有行业主管（监管）部门的还需按适用程序核准，并履行备案审核。

**`0` 处理**：该客体无已识别侵害，该项不参加最大值计算。若6项均为0，必须重新核实业务边界/事故情景，结果设为 `insufficient_impact_data`，不输出“0级”或自动判为“1级”。

**`9` 处理**：只要6项中有任何9，仍可计算当前已知维度的 `known_lower_bound_level`，但不能输出完整定级结论；展示“已知不低于X级，仍有未知影响，待复核”。

### 伪代码（可直接转规则引擎）

```python
MATRIX = {
    "rights":   {1: 1, 2: 2, 3: 2},
    "public":   {1: 2, 2: 3, 3: 4},
    "national": {1: 3, 2: 4, 3: 5},
}

INFO_FIELDS = {
    "rights": "info_rights_severity",
    "public": "info_public_severity",
    "national": "info_national_severity",
}
SERVICE_FIELDS = {
    "rights": "service_rights_severity",
    "public": "service_public_severity",
    "national": "service_national_severity",
}


def evaluate_dimension(answers, fields):
    levels = []
    unknown = False
    details = []
    for obj, field in fields.items():
        severity = answers.get(field)  # 必须区分 None、0、9
        if severity is None or severity == 9:
            unknown = True
            details.append({"field": field, "status": "unknown"})
        elif severity in (1, 2, 3):
            grade = MATRIX[obj][severity]
            levels.append(grade)
            details.append({"field": field, "severity": severity, "grade": grade})
        elif severity == 0:
            details.append({"field": field, "severity": 0, "grade": None})
        else:
            raise ValueError(f"Invalid severity in {field}")
    return max(levels, default=None), unknown, details


def initial_grade(answers):
    info, unknown_info, info_details = evaluate_dimension(answers, INFO_FIELDS)
    service, unknown_service, svc_details = evaluate_dimension(answers, SERVICE_FIELDS)
    known = [x for x in (info, service) if x is not None]
    base_level = max(known) if known else None
    unknown = unknown_info or unknown_service
    if not known:
        status = "insufficient_impact_data"
    elif unknown:
        status = "pending_review"
    else:
        status = "preliminary_complete"
    return {
        "status": status,
        "business_information_level": info,
        "system_service_level": service,
        "base_level": base_level,  # 不等于最终备案等级
        "is_lower_bound_only": unknown,
        "rationale": info_details + svc_details,
    }
```

> 此函数只实现 **D 类标准矩阵**。随后必须用独立模块处理 P/R 类已确认适用规则；T 类不能悄悄修改 `base_level`。

## 2. 特殊对象的标准原则（P 类规则）

| 规则 ID | 触发条件 | 系统处理 | 自动生效前提 |
|---|---|---|---|
| P01 | 对象是承担支撑作用的**云计算平台/系统或通信网络设施**，承载其他等级保护对象 | 原则上平台/设施等级**不低于其承载对象最高的已确认等级** | 对象类型、支撑关系和承载等级可核验；否则 `pending_review` |
| P02 | 对象为**大数据平台/系统**，同时涉及**大量公民个人信息**并**为公民提供公共服务** | 原则上不低于**三级** | “大数据平台/系统”“大量”“公共服务”的适用性均经确认；标准没有统一人数定义 |
| P03 | 独立数据资源 | 结合数据规模、价值及被破坏后的侵害客体/程度定级 | 按 D 类矩阵及具体行业规则评定；不能仅按容量定级 |
| P04 | 工控、物联网、移动互联网、云租户等特殊对象 | 要求复核定级对象边界及安全责任主体 | 第5章特殊对象划分规则；不是普遍“等级下限” |

**P02 不等于**：“只要个人信息超过1,000万人，所有信息系统都必须定为三级”。“大量”没有在该标准中被量化成统一人数字段。也不能将企业普通 CRM 自动认定为“为公民提供公共服务的大数据平台”。

## 3. 可配置内部风险预警（T 类；不代表法定等级）

| 规则 ID | 建议条件 | 建议输出 | 是否直接强制最低等级 | 来源属性 |
|---|---|---|---|---|
| T01 | `external_network_access` = 存在公众可访问入口 | `public_exposure = true`、提高审查优先级；组织**可选**“按至少二级审查”的内部工作流程 | **否** | 内部风险策略，不是国标 |
| T02 | `personal_info_count_system >= 1_000_000` | `large_pi_review = true`，核查受害人数和损害程度 | **否** | 自定义规模预警；不是等保二级门槛 |
| T03 | `personal_info_count_system >= 10_000_000` | `very_large_pi_review = true`，要求数据/业务专家复核影响客体及损害程度 | **否** | 自定义规模预警；不是等保三级门槛 |
| T04 | `personal_info_count_operator >= 10_000_000` | `regulatory_pi_10m_check = true`，触发《网络数据安全管理条例》第28条等**主体层面**义务核查 | **否** | 法规合规触发器，但**不是等保等级阈值** |
| T05 | 有敏感个人信息/不满14周岁未成年人信息 | 提醒隐私影响、敏感数据泄露后果须充分评估 | **否** | 影响分析佐证/隐私法规 |
| T06 | 处理重要数据、核心数据，或已被正式认定为关键信息基础设施 | 触发行业适用性、责任主体、R类规则及特殊保护义务核验 | **否，除非另有经核验的适用定级规定** | 法规/行业复核 |
| T07 | 属于全国服务、大范围公共服务、核心生产/交易或有跨系统影响链 | 要求评估公共利益影响，核对 F08、F11 | **否** | 影响分析佐证 |

**数量阈值政策**：T02、T03 的 100万、1000万人是本**示例模板的可配置审核分档**，并非 GB/T 22240-2020 规定的二级/三级最低人数。保留这些分档是为了让自动化系统快速发现大规模数据处理场景，但必须允许组织按行业/风险偏好调整、关闭并留存审批记录。实际法规适用时按相应规定计算主体、口径和生效时间。

可选的内部候选提示字段（**默认不参与国标计算**）：

```yaml
    enabled: true
    candidate_review_level: 2
    affects_national_standard_grade: false
  personal_info_one_million:
    enabled: true
    min_subject_count: 1000000
    candidate_review_level: 2
    affects_national_standard_grade: false

    enabled: true

```

## 4. 监管和行业要求（R 类）管理机制

**不要把传闻、销售资料、以前客户的等级、地方惯例或者无适用性的行业规范写成通用强制规则。** 每个 R 类约束须有下列信息：

```yaml

  - rule_id: "R-EXAMPLE-001"
    title: "请填写适用的行业或主管部门定级要求"
    citation_url: null
    article: null
    issuing_authority: null
    version: null
    effective_from: null
    effective_to: null
    industry: null
    applicability_conditions: []
    action: "manual_review"    # 只有经核验且确有等级下限时才可设 minimum_level
    minimum_level: null
    approved_by: null
    reviewed_at: null
```

同一组织的自愿内部防护基线、合同约定与法定等级结果需分别输出。若内部安全政策要求“互联网系统统一按至少二级控制措施建设”，可形成**建设控制基线**，但不能因此改变公安备案所需的国标定级事实。

## 5. 完整判定优先级与输出字段

**优先级**：定级对象有效性 → D矩阵 → 适用且证据充分的P原则 → 适用且经核验的R规则 → T风险预警（只提示、不改国标等级） → 专家/主管部门/备案审核。

```json
{
  "system_id": "SYS-001",
  "standard_version": "GB/T 22240-2020",
  "rule_engine_version": "1.0.0",
  "status": "preliminary_complete",

  "system_service_level": 1,

    {"id": "F10", "object": "rights", "severity": 1, "matrix_level": 1}
  ],
  "final_confirmed_level": null

```

**状态定义**：

- `draft`：尚未提交。
- `insufficient_impact_data`：核心定级信息缺失或全部没有可分析影响。
- `pending_review`：关键题为9/缺失，特殊规则待确认，或发现重大矛盾。
- `preliminary_complete`：六项核心影响已回答，完成国标矩阵计算；**仍不等于最终备案通过**。
- `expert_reviewed`：已完成适用的专家评审。
- `regulator_reviewed`：已完成适用的行业主管部门核准。
- `filed_confirmed`：完成相应备案审核、等级获确认。

**建议输出三列**：`国家标准初步等级`、`内部建议审核强度`、`法规/行业附加约束`；避免只输出一个“综合总分”。

## 6. 自动校验与人工复核触发器

| QA ID | 校验条件 | 处理 |
|---|---|---|
| QA01 | B02/B03/B04 任意为否或不确定 | 核实是否为独立定级对象；阻止最终定级建议 |
| QA02 | F07–F12 有 `9`、缺失或六项全为0 | 不自动形成完整等级；展示缺失与待核实原因 |
| QA03 | D02=否，但D01包含个人信息、D03>0、D05选了敏感PI | 标为答案矛盾，要求修改 |
| QA04 | B06显示公众可访问，F07–F12均为0 | 核实业务影响，不按公网默认升级 |
| QA05 | C06=是、E07=是或E06影响公共服务，但F08=F11=0 | 提醒核实公共利益受损情景；不自动覆盖答案 |
| QA06 | 国家安全维度 F09/F12 >0 | 强制高级人工复核并取得书面理由 |
| QA07 | P01所承载的最高等级大于D类计算结果 | 在核验证据后应用支撑平台“原则不低于”校验，留痕 |
| QA08 | P02条件看似满足但“大量”与“公共服务”未核实 | 专家审查、禁用自动硬性三级下限 |
| QA09 | D04达到1000万人但系统D03较小 | 启动处理者层面合规提示，**不得以D04自动提高当前系统等级** |
| QA10 | 任何规则建议等级高于D类结果、但没有明确来源/适用条件 | 标注“内部建议”或“待复核”，不得冒用法定下限 |
| QA11 | E01与 E02/E03 的停机后果明显不一致 | 要求解释停机容忍度、替代措施和事件情景 |
| QA12 | G06历史等级高于初定等级 | 提示等级变更核对，要求填写业务与数据变化及审核依据 |

### 可信度辅助指标（**不参与定级**）

如需进行项目管理评分，可以为**证据完整度**单独计算0–100分，表示资料质量而非系统安全保护等级：

- 核心影响题 F07–F12 有确定答案（不为9）：40分；缺失则按比例扣除。
- 系统边界与责任主体 B02–B04 已核实：20分。
- 数据规模与数据分类 D01–D11（适用项）有统计依据：15分。
- 业务影响分析 E01–E08 具备量化证据：15分。
- 监管/平台原则 G01–G05 适用性已确认：10分。

可据此决定是否进入专家评审，但不得将“证据80分”解释为“等保三级”。

# 第三部分：自动定级运行示例

### 示例 A：仅面向内部的采购审批系统

- 内网部署，300名员工使用；不承担公共服务；发生数据篡改会造成企业经营损失。
- 核心输入：F07=2（合法权益严重）；F08=0；F09=0；F10=1；F11=0；F12=0。
- **国标矩阵**：业务信息安全=2，系统服务安全=1 → **初步二级**。
- 关键原因是**受侵害客体和损害程度**，不是是否内网部署。

### 示例 B：公网开放的普通展示网站

- 公众可访问，但仅发布公开信息，无重要交易；经审查仅可能对单位合法权益造成一般损害。
- 核心输入：F07=1；F08=0；F09=0；F10=1；F11=0；F12=0。
- **国标矩阵**：**初步一级**；T01触发“公网开放，建议至少按内部二级控制强度复核”的预警。
- **不能**因为公网访问直接宣称“法定最低二级”。若实际上会影响公共服务或造成其他严重后果，应修正F项重新计算。

### 示例 C：全国性公共服务平台

- 提供重要公众服务，服务中断可能对公共利益造成严重损害。
- 核心输入：F07=2；F08=1；F09=0；F10=2；F11=2；F12=0。
- **国标矩阵**：业务信息安全=max(2,2)=2；系统服务安全=max(2,3)=3 → **初步三级**。
- 并非“全国用户自动三级”，而是经确认的**公共利益严重损害**对应三级。

### 示例 D：处理1,200万人个人信息的企业应用

- D03=12,000,000；因此T02/T03触发；如果处理者整体也达到1,000万人，D04还触发相关法规合规审查。
- **仅凭1,200万人无法得出法定等保三级**；仍需完成 F07–F12 的影响判断。
- 若该对象是经核实符合“涉及大量公民个人信息且为公民提供公共服务的大数据平台/系统”的特殊对象，则可依GB/T 22240-2020第7章应用**原则不低于三级**的标准原则（需要证据确认）。

# 第四部分：开发实施建议

## 1. 前端问卷实现

- **步骤式表单**：A系统概况 → B边界部署 → C服务范围 → D数据 → E业务影响 → F核心定级 → G监管/复核 → H附件。
- **动态显示**：如D02=否隐藏D03–D07（但若D01选择敏感信息需先处理矛盾）；B01=云平台时显示B09；B01=大数据平台时显示D11/G04。
- **不确定态**：每个关键题允许“不确定”，但页面必须提示“会触发人工复核”。
- **问卷提交**：自动先运行 QA01–QA12，再进行核心矩阵计算；发现重大矛盾时仅展示“待补充信息”。
- **可解释结果页**：显示F项作答、标准矩阵命中单元、触发的P/R/T规则、证据链接和复核意见。

## 2. AI 可以做什么，不能做什么

**适合AI完成**：从PRD、业务流程图、架构图、数据字典、BIA及行业通知抽取A–E/G项；根据客观事实**建议**F07–F12的受侵害客体和程度；给出候选事故链、引用证据并提示矛盾。

**不能让AI直接做**：根据“公网/百万个人信息/某行业”直接生成最终等保等级；无证据断言国家安全影响；跳过专家评审、行业核准及公安备案审核。

## 3. 建议数据库实体

`systems`、`questionnaire_versions`、`questions`、`question_options`、`answers`、`evidence_files`、`impact_scenarios`、`rule_registry`、`rule_executions`、`review_decisions`、`classification_reports`、`audit_logs`。

存储每次评估的**问卷版本、标准版本、规则版本、答案快照、证据、评审意见、等级变化原因**。数据规模、公共服务范围、主营业务发生变化时，提示重新定级。

## 4. 最小产品版本（MVP）建议

**MVP必需**：A/B/C/D核心信息、F07–F12六项影响题、国标矩阵、T01/T02/T03预警、QA校验、证据上传与结果解释。  
**第二阶段**：行业R规则库、特殊对象P规则、AI辅助填报、版本管理、专家复核与报告生成。

**本模板的规则边界**：

- `D` 是国家标准的**直接定级输入**。
- `P` 是特殊定级对象在条件成立且完成适用性核验后的**标准原则**。
- `R` 是另有适用条款并已经核实的**监管/行业约束**。
- `T` 是组织内部自主设立的**风险预警与审查强度建议**，不是法定等保下限。
- 本系统最多生成可解释的**初步等级建议**，最终等级应按适用的评审、核准和备案审核程序确定。
