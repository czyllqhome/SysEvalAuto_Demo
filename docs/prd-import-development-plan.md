# PRD 自动导入与更新开发计划

状态：已按本方案实现第一版；实际接口与限制见 [实现说明](prd-import.md)。本文仅包含功能与实现内容，不包含人力或项目周期安排。

## 1. 功能目标

用户在初次填写系统描述前，可以上传已有 Markdown PRD。系统将文档发送给已配置的外部大模型，查找当前页面要求填写的全部八类描述内容，将找到的内容自动填入对应输入框并保存为可编辑草稿。

**找不到的内容保持空白，不要求模型补齐、不生成推测性业务内容。** 用户不需要逐字段点击接受，便可获得首次自动填充结果；之后可以直接修改、补充或撤销。自动填充不代表确认应用说明、确认等级或批准 PRD。

同时支持已有描述时导入，以及上传新版 PRD 更新描述。已有人工内容必须保留，冲突通过差异选择处理。

## 2. 提取与字段映射

每次解析必须检查以下全部八个主题，不能只提取文档标题对应的章节。模型需从全文的标题、段落、列表、表格中查找相关信息；同一主题分散在多处时合并整理，并保留来源。

| 当前输入主题 | 字段键 | 必须查找的内容 | 未找到时 |
| --- | --- | --- | --- |
| 建设目标 | `goal` | 系统定位、业务背景、服务对象、需要解决的问题、预期目标与价值 | 留空 |
| 功能与范围 | `functions` | 本期功能、用户操作、功能边界、明确暂不实施的功能 | 留空 |
| 涉及部门 | `people` | 使用部门、业务部门、运营与支持部门、参与的外部团队 | 留空 |
| 负责人及角色 | `responsibility` | 业务责任角色，以及操作、审批、维护、验收角色；已明确的负责人 | 留空 |
| 业务流程 | `workflow` | 从发起到结束的流程、审批步骤、驳回、异常和失败处理 | 留空 |
| 数据与接口 | `data` | 录入、读取、导出和存储的数据，外部系统、接口与集成关系 | 留空 |
| 交付约束 | `constraints` | 时间、可用性、性能、访问量、预算、部署及其他明确限制 | 留空 |
| 边界与验收 | `acceptance` | 本期范围、明确不做的事项、验收标准、成功和失败场景 | 留空 |

### 2.1 内容整理规则

- 八个字段都必须在模型结果中返回，未找到内容时使用空字符串和空来源列表。
- 某主题只找到部分信息时，填入找到的部分，其余部分不补写。例如仅识别到审批角色，不编造业务负责人。
- 内容可以归纳、去重和调整顺序，不能增加原文没有的功能、人员、数值、接口、验收指标或承诺。
- 保留否定、条件、单位、范围和不确定性。例如“预计”“待定”“暂不包含”不能改成确定要求。
- “未提及”与“明确无此要求”不同。原文明示“无外部接口”时应填入该内容，不能当作空白。
- 原文明示“负责人待定”时保留该信息；原文完全未提及负责人时，不自行填入“待定”。
- 同一证据可支持多个主题，但避免重复铺陈。例如业务范围可同时支持功能清单和边界描述。
- 原文存在矛盾时，保留不冲突的信息；冲突部分独立展示双方证据，不擅自选取结论。
- 不以界面语言变化翻译或重写原文。提取内容沿用原文表达语言，界面提示提供中英文。

### 2.2 系统名称

系统名称在创建系统时单独填写，不属于八个描述输入框。本次同时允许从 PRD 中提取名称候选：目标名称为空时可填入，已有名称时仅展示建议，替换须用户主动选择。不能因导入而自动重命名已有系统。

### 2.3 示例

PRD 原文：

> 本系统供采购部门使用。本期支持采购申请、主管审批和订单查询，不包含付款功能。

预期填充：

| 主题 | 填充值 |
| --- | --- |
| 建设目标 | 为采购部门提供采购申请、审批和订单查询能力。 |
| 功能与范围 | 采购申请；主管审批；订单查询。本期不包含付款功能。 |
| 涉及部门 | 采购部门。 |
| 负责人及角色 | 主管：审批。 |
| 业务流程 | 空白；仅列出功能不应被扩写为完整流程。 |
| 数据与接口 | 空白。 |
| 交付约束 | 空白。 |
| 边界与验收 | 本期覆盖采购申请、主管审批和订单查询，不包含付款功能。 |

## 3. 用户流程

1. 在“描述系统”页面顶部显示“从已有 PRD 导入”，用户尚未填写任何主题时即可操作。
2. 用户选择单个 `.md` 文件，页面显示文件名、大小及安全文本预览。
3. 用户点击“解析并自动填充”。按钮旁明确说明将通过已配置的外部模型解析文档。
4. 系统保存文档并启动后台任务，显示排队、解析中、完成或失败状态。
5. 解析期间允许继续输入；应用结果时重新检查字段和草稿版本，避免覆盖新输入。
6. 解析成功后，系统自动将有来源、无未解决冲突的结果填入当前空白字段，保存草稿，无需逐项接受。
7. 显示处理摘要，例如“已自动填充 6 项，2 项未找到内容”。未找到项保持空白，并可通过独立提示定位。
8. 每个已填字段显示“来自 PRD，待核对”，可查看来源章节与摘录、编辑或撤销本次应用。
9. 用户继续现有等级确认和应用说明审查流程。

上传、预览、刷新页面和普通自动保存均不启动新的模型调用。任务完成后的自动填充由服务端执行，使用户关闭页面后重新打开也能恢复结果。

## 4. 首次填充与新版更新规则

| 当前状态 | 应用规则 |
| --- | --- |
| 字段为空，PRD 中找到有效内容 | 自动填入并保存 |
| 字段为空，PRD 未提及 | 保持空白，不写入“未提及”等占位文本 |
| 字段已有人工内容 | 保留，显示导入建议，允许用户替换或编辑合并 |
| 字段由上一版导入填充，之后未修改 | 新版解析后展示差异，用户可批量应用更新 |
| 字段由上一版导入填充，之后被修改 | 标记冲突，由用户选择保留、替换或编辑合并 |
| 新版未找到旧版已有内容 | 保留已有值，提示“新版未发现”，不自动删除 |
| 新版明确取消已有功能或约束 | 展示取消建议，用户确认后应用 |
| 解析期间发生人工编辑 | 保留最新值，将对应提取结果转为建议 |
| 文档自身存在矛盾 | 不自动填入相互冲突的结论，展示证据供用户处理 |

“未找到留空”适用于尚为空的字段，不代表清空已有内容。新版更新先比较再应用，防止损失用户修订。

### 4.1 撤销与重复导入

- 提供“撤销本次填充”，记录每个字段应用前后的值。
- 仅撤销当前值仍等于本次应用结果且版本检查通过的字段；后续已编辑的字段保留并提示。
- 使用文件内容哈希识别同一系统内的重复上传，符合版本与配置条件时复用已有解析结果。
- 如需更换模型或重新解析，提供明确操作并创建新提取记录。
- 重复请求不能重复应用字段或创建同一逻辑任务。

## 5. 文档处理与模型任务

### 5.1 Markdown 校验和来源定位

- 第一版支持单个 Markdown 文件，不支持 PDF、Word、图片识别或批量文件合并。
- 校验扩展名、文本编码、空内容、文件大小和输入 token 预算；明确支持 UTF-8 和 UTF-8 BOM。
- 配置文件与模型输入上限。超限返回明确提示，不静默截断；长文档分段提取列为后续扩展。
- 按标题、段落、列表和表格拆分来源片段，分配服务端来源 ID，保存章节路径、行号和原文。
- 保留原始 Markdown 与内容哈希，不执行文档中的代码、HTML 或指令，不主动抓取链接和远程图片。
- 发送模型前沿用现有敏感内容处理，维护处理后文本到原文的定位关系；日志不记录完整 PRD 或凭据。

### 5.2 新增提取任务

新增 `prd_import_extraction` 任务类型，复用现有 OpenRouter、持久化任务、租约、重试、用量记录和组织级模型配置。

任务快照包括文档版本、文档哈希、草稿版本、模型配置、提示词版本和字段映射版本。模型只负责提取候选内容，不直接决定数据库写入或系统阶段变化。

结构化结果应包含：

- 固定八个字段，每个字段具有 `text`、`source_ids`、`evidence` 和提取状态。
- 提取状态区分“已找到”“未找到”“存在冲突”。
- 系统名称候选及其证据。
- 冲突列表、缺失主题列表和必要的待澄清问题。

服务端验证字段白名单、数据类型、字段长度、来源 ID 和证据摘录。八个字段长度沿用现有描述输入限制；超限不能直接截断后保存。未知字段、伪造引用、无效 JSON、截断输出和拒绝响应均不能进入自动填充。

有效来源不等于模型语义已经完全正确，填充结果始终属于待核对草稿。

### 5.3 模型配置与失败处理

- 在现有 AI 设置中增加“PRD 导入提取”提示词模板，支持组织级编辑与恢复默认。
- 结构、来源、权限与更新规则由服务端固定，不因管理员修改提示词而被绕过。
- API 密钥保持在服务端配置，不存入导入记录或返回前端。
- 未配置模型时展示配置提示，保留手动填写能力。
- 超时、额度不足、网络或校验失败时保留文档与草稿，提供错误说明和明确重试入口。
- 不将规则生成内容冒充模型提取结果，不在模型失败时静默执行本地替代。

## 6. 草稿与后续流程衔接

导入目标是当前 `draft.blocks` 中的八个主题，复用现有自动保存与后续整理流程：

`PRD 导入 → 八个主题自动填充 → 用户补充 → 确认等级 → 整理并审查应用说明 → 确认后匹配控制`

- 保存每个导入字段与原始文档片段的关联，后续整理的业务功能仍能追溯至文档版本。
- 修改描述后，将依赖旧描述的应用说明建议标记为过期，要求重新整理或核对。
- 导入阶段允许字段为空，不为了满足后续必填要求而虚构内容。
- 应用说明确认阶段继续检查目标摘要、功能、部门、角色、业务责任角色、范围等现有必填条件。
- 第一版不自动填充分级问卷、不选择等级、不确认控制、不生成批准状态或供应商承诺。
- 如后续扩展问卷提取，必须适配当前 SYS-SCREEN/2 的事实字段，用户接受后才参与规则评估。
- 初期草稿可直接应用导入结果；已进入下游审查的系统须先展示影响，通过现有修订机制更新。
- 确认后的描述发生变化，保留历史成果，失效处理受影响的分级、应用说明、PRD、报告与基线确认。双方必须独立确认同一个新基线哈希，旧确认不得迁移。

## 7. 数据与接口设计

### 7.1 持久化记录

通过增量迁移增加必要记录，运行数据继续存于 `.syseval/assessment.db`，不得清空现有记录和备份。

| 记录 | 主要内容 |
| --- | --- |
| 导入文档版本 | 系统与组织归属、文件名、原文、哈希、上传人、时间、上一版本 |
| 提取结果 | 文档版本、任务 ID、配置快照、八字段候选、来源、缺失项、冲突项 |
| 字段应用记录 | 字段键、应用前后值、草稿版本、来源、自动或手动应用、操作者、撤销状态 |

沿用组织和项目权限。仅具备对应系统描述编辑权限的用户可以上传、解析或应用；只读用户不能通过导入接口修改内容。来源文档默认不向供应商额外开放。

### 7.2 拟新增接口

以下接口已实现；路径均以 `/api/v1` 为前缀。

| 接口 | 用途 |
| --- | --- |
| `POST /systems/{id}/prd-imports` | 上传并创建文档版本 |
| `GET /systems/{id}/prd-imports` | 查询导入历史 |
| `GET /systems/{id}/prd-imports/{import_id}` | 查看文档、结果、来源与差异 |
| `POST /systems/{id}/jobs` | 复用任务入口，以新任务类型开始解析 |
| `POST /systems/{id}/prd-imports/{import_id}/apply` | 应用用户选择的更新 |
| `POST /systems/{id}/prd-imports/{import_id}/undo` | 撤销符合条件的应用 |

首次自动填充与手动应用使用同一服务端应用函数。完成任务时检查任务有效性、文档版本、权限、阶段和最新草稿版本；使用事务原子保存字段及审计记录。过期任务不得写入，冲突字段转为建议，前端刷新数据而不是用旧快照覆盖新文本。

## 8. 实现工作拆分

| 顺序 | 功能工作 | 涉及现有模块 | 完成标准 |
| --- | --- | --- | --- |
| 1 | 导入数据、权限、上传校验和文档预览 | `db.py`、迁移、API 路由及新增导入模块 | 文档可保存和恢复，越权访问被拒绝 |
| 2 | 八字段提取契约、来源分段和模型任务 | `domain.py`、`ai.py`、`ai_settings.py`、`worker.py` | 每次返回全部八字段，未找到为空，证据可核验 |
| 3 | 自动填充、保存、来源标记、撤销与并发保护 | `service.py`、`narrative.tsx`、新增导入组件 | 首次导入自动填入空白字段，无需逐项接受 |
| 4 | 新版差异、人工修改识别、批量应用 | 导入模块、应用记录、差异组件 | 可更新旧导入内容，人工修改不丢失 |
| 5 | 整理来源传递和下游修订保护 | 应用说明与现有修订流程 | 来源可追溯，更新不会绕过确认流程 |
| 6 | 中英文文案、回归验证和文档更新 | `i18n.tsx`、前后端测试、项目文档 | 通过全部相关检查，文档反映实际行为 |

新增依赖仅在 `backend/pyproject.toml` 或 `frontend/package.json` 中维护。实现时更新 README、实现说明和开发规范中的受影响流程，明确区分已实现与规划内容。

## 9. 验收与离线回归

模型相关业务回归使用固定 Markdown 样例和模拟响应，不依赖真实密钥或付费调用。

| 场景 | 预期结果 |
| --- | --- |
| 文档包含全部八类内容 | 八个输入框自动填入，刷新后仍保留 |
| 文档仅包含业务范围 | 对应主题自动填入，其他字段为空 |
| 文档某主题只有部分信息 | 仅填入已找到部分，不推测缺失内容 |
| 同一主题分布在多个章节或表格 | 合并相关内容，并保留多处来源 |
| 文档未提及接口／明确无接口 | 前者留空，后者填写“无接口” |
| 包含否定、单位、待定或排除项 | 保留原意，不改成确定承诺 |
| 文档自相矛盾 | 冲突独立展示，不自动采用单一结论 |
| 现有人工内容或解析期间编辑 | 不覆盖，提取结果作为建议 |
| 上传新版，旧导入值未修改 | 显示差异，可批量应用 |
| 新版遗漏旧内容或明确取消功能 | 不静默清空，显示更新或删除建议 |
| 撤销后存在后续人工编辑 | 只还原安全字段，保留人工编辑 |
| 重复上传、重复请求、任务重试 | 不重复应用，记录保持一致 |
| 超限、非文本、空文件、编码不支持 | 返回明确错误，不启动无效模型任务 |
| 模型失败、截断、伪造引用或输出未知字段 | 不污染草稿，错误可见，可按策略重试 |
| 文档含模型指令或不安全 HTML | 作为数据处理，不执行、不改变提取约束 |
| 切换中英文 | 界面切换，原文与填充值不变 |
| 跨组织或无编辑权限 | 拒绝读取受保护内容或进行写入 |
| 旧任务迟到、并发更新、已进入下游阶段 | 版本与状态检查阻止错误写入 |
| 更新已确认内容 | 按修订机制重新审查，不复用旧基线确认 |

实现完成后在项目根目录执行：

```powershell
uv run --project backend --extra dev python -m pytest evals/deterministic -q
uv run --project backend --extra dev ruff check backend/app backend/migrations evals run.py
npm --prefix frontend test
npm --prefix frontend run build
```

## 10. 本次开发边界

后续扩展：多文件合并、超长文档分段提取、PDF/Word 导入、图片 OCR、分级问卷候选事实提取。上述能力不作为本次完成前置条件。
