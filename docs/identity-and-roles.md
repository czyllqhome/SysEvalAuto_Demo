# 身份、项目角色与管理审计

## 当前 Demo 的 RBAC 职责矩阵（2026-11-05）

管理员在左侧“配置 → RBAC 职责矩阵”（`/rbac`）查看六类角色的职责、授权范围和业务操作权限。
页面提供中英文说明，以“可执行 / 有条件 / 不授予”区分权限，并可跳转“人员与权限”管理实际授权。
入口和页面均限定管理员；非管理员直接访问仅显示无权查看。矩阵为只读参考，不调用业务写入或模型接口。

当前 Demo 以组织角色和单个评估成员授权为准，取代下文历史项目授权操作步骤：

| 角色 | 当前范围与职责 |
| --- | --- |
| 系统管理员 | 本组织全部评估、账号及组织角色、控制来源上传、AI/PRD 配置和管理审计；拥有全部客户方评估操作权限。 |
| 负责人 | 可直接创建评估；仅管理自己创建或获管理授权的评估，可编辑、评审、分派普通成员、下发及进行客户方基线确认。 |
| 经办人 | 按评估授权，填写问卷、调整控制范围、编辑 PRD 及核验/整改记录；不因此获得审批或基线确认权限。 |
| 评审人 | 按评估授权，审批 PRD、审查风险及核验报告、复测和交付证据；已有该评估编辑贡献时仅保留读取权限。 |
| 只读成员 | 读取明确授权评估的内容、结果和进度。 |
| 供应商 | 独立身份，仅处理明确下发的任务；提交需求答复和交付证据，独立确认供应商基线。 |

组织角色不自动开放其他人的评估；具体操作由该评估的成员角色决定。成员授权入口只允许调整普通账号的经办、评审和只读角色，不能用于授予负责人或管理员。客户与供应商仍需分别确认同一基线哈希。

交付验收保留原有特例：经办人必须同时匹配原 `Assignment.operator_id` 且仍具编辑权限，才能审核供应商交付证据；仅有直接评估经办授权不足。此特例不授予 PRD、报告或基线审批权，且不得审核本人提交。

English: Administrators can open Configuration → RBAC matrix to compare six roles across 16 actions. Current access uses organization roles plus individual assessment grants. Managers act only on assessments they own or manage; ordinary reviewers with editing contributions retain read-only access. Supplier responses and confirmations require an independent supplier identity. Delivery review retains its original task-operator exception. This bilingual reference page changes neither authorization rules nor runtime records.

## 角色现状与本次修复

顶部账号身份优先显示系统管理员，不能从基础账号类型 `owner` 推断管理员是客户负责人。
角色说明、授权选项及管理员徽标只显示当前界面的语言，不附带内部角色代码。
账号显示名按保存值展示，不随界面语言切换翻译。

当前角色由两层组成：组织管理员标记，以及用户在具体项目中的业务角色。
数据库中的 `owner`、`member`、`vendor` 是基础账号类型，不是界面中的项目角色
的替代字段。管理员拥有本组织全部项目权限；业务负责人拥有所负责项目的全部客户方权限。普通项目角色可兼任。

此前后端已经支持四种项目角色，但新增账号只填写登录名和姓名，项目授权隐藏在
每个账号的折叠区域中。没有项目时无法授权，页面也缺少直接的下一步提示，
容易误以为只支持“撤销管理员”。

本次修复包括：

- 账号以可搜索列表显示；点击姓名或“配置”后，在独立弹窗中管理组织权限和项目角色。
- 新增账号可选择初始项目和一个或多个业务角色，账号、授权与管理审计同事务保存。
- 没有项目时明确提示先创建项目；新建项目自动成为新增账号表单的可选授权项目。
- 账号配置弹窗分别显示组织管理权限、已授予的项目角色、启停状态与保存结果。
- 修改本人权限后立即返回登录，避免继续使用已撤销的会话。
- 中英文切换保留输入的姓名、项目名、所选项目和角色；失败时保留待提交内容。

## 角色与权限

| 角色 | 分配入口与范围 | 当前权限 |
| --- | --- | --- |
| 系统管理员 `admin` | 账号配置弹窗的“组织管理权限”，作用于当前组织 | 本组织全部项目进度及业务权限、直接分派、管理账号、创建项目、授权角色、启停账号、重置密码与审计 |
| 业务负责人 `manager` | 新增账号时或账号配置弹窗的“项目角色授权”，作用于所选项目 | 所负责项目全部客户方权限，包括编辑、评审、普通角色授权、分派、下发、协商及最终确认 |
| 业务经办人 `operator` | 同上；还须被负责人分派到具体评估 | 修改受派评估的资料、问卷和业务草稿，执行允许的编辑和生成操作 |
| 评审人员 `reviewer` | 同上；还须被负责人分派到具体评估 | 读取受派评估，审批 PRD、审查影响分析及相关评审操作 |
| 只读查看者 `viewer` | 同上，作用于所选项目 | 查阅项目评估，不能编辑、审批或管理账号 |
| 供应商项目角色 `supplier` / 账号类型 `vendor` | 管理员创建账号或项目授权；也保留外部邀请入口 | 独立供应商身份，仅查看和答复已下发的 PRD，参与协商并确认同一基线 |

管理员可查看本组织全部项目进度，执行编辑、评审和客户方最终确认，直接授权及分派任务，无需先授予本人业务负责人角色，也无需负责人再次分派。
业务负责人拥有其授权项目的全部客户方权限，可为普通账号授予或撤销经办、评审、只读和供应商角色；不能授予 Admin 或负责人，也不能修改已有 Admin 或负责人账号。
普通经办人、评审人仍需要具体任务分派；历史经办人不能以普通评审角色审核本人填写内容。管理员和负责人可跨客户方阶段操作，但供应商仍必须独立确认同一基线哈希，版本、来源及组织边界检查不变。

管理审计从导航栏的“审计日志”进入 `/audit`，不再显示在人员配置页面。
支持操作代码、操作人、开始/结束日期筛选，以及每页 30 条的翻页。
日期按浏览器本地时区解释，结束日期包含当天。列表只加载摘要，点击“查看详情”
才读取并显示完整记录。迁入历史可切换来源查看、关键词筛选和分页，最多读取 1000 条。
列表与详情接口均仅 admin 可读，并限制为当前组织；业务来源与修订历史仍沿用原业务授权。

左侧“项目与任务分派”入口集中管理账号授权、创建评估及已有评估分派；各阶段页不再重复显示分派表单。管理员可看到全部评估，负责人可看到所负责项目评估。未关联评估可由管理员建立同名项目后直接关联和分派。

## 操作步骤

1. 使用管理员账号进入“项目与角色”。
2. 在“新增项目”填写项目名称并创建。管理员自动拥有该项目权限。
3. 在“新增账号并分配角色”填写登录名、姓名，选择初始授权项目，勾选一个或多个
   业务角色，点击“创建账号并授权”。临时密码仅显示一次，首次登录必须修改。
4. 已存在的账号无需重新创建：点击列表中的姓名或“配置”，在弹窗的“项目角色授权”中选择项目、勾选角色，点击
   “保存项目角色”。保存只替换所选项目的角色，不影响其他项目。
5. 若要撤销项目访问，取消该项目全部角色后保存。不要用“撤销管理员”替代业务角色设置。
6. 管理员或项目负责人，在“建立项目评估任务”中指定经办人和评审人。

可只创建账号、暂不授权项目，但此账号不因此获得项目访问权。选择了初始项目时，
必须同时选择至少一个角色。供应商角色 `supplier` 与客户方角色互斥。不能授予基础账号类型 `vendor`、
`admin` 或任意自定义角色代码。管理员标记通过独立管理操作设置。

权限调整会撤销受影响账号的会话；如调整的是本人，页面会立即返回登录。
至少保留一个有效管理员，禁止停用或撤销最后一位管理员。

## 接口与原子性

新增账号请求：

```http
POST /api/v1/admin/users
```

```json
{
  "username": "project-operator",
  "name": "业务经办人",
  "project_id": "authorized-project-id",
  "roles": ["operator"]
}
```

只创建账号时同时省略 `project_id` 和 `roles`。如果提供其中任意一个字段，
必须提供有效的同组织项目和非空、无重复的固定业务角色列表。
非法角色、其他组织项目、停用项目或授权写入失败均不会留下新账号或成功审计记录。

已有账号授权保持原接口：

```http
PUT /api/v1/admin/projects/{project_id}/members/{user_id}
```

```json
{ "roles": ["manager", "viewer"] }
```

传入空列表表示撤销该项目授权；管理员标记继续通过
`PUT /api/v1/admin/users/{user_id}` 的 `is_admin` 字段单独管理。
创建账号仅限管理员；已有账号项目授权也允许该项目负责人操作普通账号。服务器检查权限层级、组织边界、账号与项目状态。
管理审计记录授权目标与角色，不记录临时密码。

## 验证

离线回归覆盖四种初始角色、组合角色、临时密码强制更换、跨组织拒绝、非法角色拒绝、
授权故障回滚和最后管理员保护。前端覆盖授权入口可见、已有账号授权与撤销、
新建项目后的引导、语言切换保留输入、失败保留输入、本人权限变更后的会话退出，
以及非 admin 不请求管理审计。验证使用隔离测试库，不修改真实账号、项目或评估。

业务负责人也可在负责评估的控制审查阶段补充项目专属控制或人工调整纳入范围。
该操作记录为编辑贡献；负责人也可编辑其他资料、评审和进行客户方最终确认。

### 审计查询接口

`GET /api/v1/admin/audits` 支持 `q`、`actor_id`、`start`、`end`、`offset`、`limit`
和 `summary`。时间为 Unix 秒，start 包含边界、end 不包含边界；limit 为 1–300。
`summary=true` 不返回 detail；省略时保持旧返回结构。排序为时间与 ID 降序。
`GET /api/v1/admin/audits/{id}` 返回同组织单条记录详情，跨组织返回 404。
新增离线回归覆盖筛选、翻页、详情延迟读取、组织边界及未关联评估发现；前端覆盖
用户搜索、配置弹窗、同名项目创建、独立审计筛选与非管理员禁止读取。


## 项目供应商账号（2026-10-28）

管理员在新增账号时选择项目并勾选“供应商”，一次创建独立供应商组织、临时密码账号和项目授权。首次登录须改密。已有未授权、无客户业务记录且非管理员的账号也可授权为供应商；已有客户业务职责的账号需要另建供应商账号，不能转换或兼任。供应商不能成为客户组织管理员。

供应商项目授权只决定下发候选范围，不直接暴露项目内全部评估。负责人在已审核 PRD 的“供应商”页选择供应商账号并下发，供应商登录后才能查看对应 PRD 与控制要求、保存和提交逐项答复。业务经办人维护资料与需求修订，评审人审查答复影响，负责人处理下发、协商与客户最终确认；供应商独立确认同一基线内容哈希。原有邮箱邀请仍可使用。

每个直接创建的供应商账号使用独立供应商组织，防止同项目其他供应商读取其任务。`managed_suppliers` 仅记录客户管理员对该账号的管理关系。撤销项目角色立即撤销会话和该项目访问；停用与密码重置仍由创建方管理员管理，即使该账号已无项目角色。已发布 PRD、历史答复和确认记录保留。

新增 `GET /systems/{id}/supplier-candidates`，下发接口支持 `supplier_user_id`，并核验所属客户组织、项目授权、账号状态及审核状态。部署需执行 `managed_suppliers` 增量迁移；本地启动自动创建缺失表。离线测试覆盖跨组织/跨供应商隔离、角色互斥、撤销访问以及从答复到同哈希双方确认的完整流程。

项目负责人创建评估：管理员先在“项目与任务分派”创建项目，并赋予指定账号
manager（负责人）角色。负责人重新登录后可在首页点击“开始新的评估”，选择
所负责项目并创建。新评估自动关联该项目，创建人直接拥有管理及填写权限，
无需先分配另一名经办人。普通经办人、审查人、查看者不能因此创建项目或评估。

## Delivery review permission update (2026-11-02)

Organization administrators, assigned project managers, eligible task reviewers and the
current task operator can review independently submitted supplier delivery evidence.
This action-specific allowance does not grant operators PRD, report or baseline approval.
Suppliers can only upload and submit within their assigned delivery scope and cannot review.
Revoked project access also blocks historical attachment downloads and receipt replays.
