## 合并后的操作路径

2026-10-25 角色入口修复：管理员标记与项目业务角色分别显示，新增账号时可一并
选择初始项目和角色，已有账号下方直接显示项目授权表单。没有项目时先创建项目，
再创建或授权账号，最后由负责人分派任务。详见[身份与项目角色](identity-and-roles.md)。

原八步顺序保持为：描述系统、确认等级、审查应用说明、控制审查、PRD 文档、
供应商、影响评估、双方确认。中英文切换保留用户填写的原文。

- 确认等级：展开 19 项详细问卷，按外网与部署、数据处理、业务连续性、系统交互
  分组填写。保存草稿或提交后带入可推导的分级依据；原始自然语言描述无需重填。
  手动等级仍允许跳过未完成的详细问卷并记录理由。
- 问卷提交后锁定，由项目负责人退回后再修改。变更已确认的事实会使下游结果失效，
  回到分级与审查；旧修订和审计保留。
- 供应商 CSV：问卷阶段可建立固定模板；供应商答复阶段可下载 PRD 对应模板。
  仅填写 value 列，上传后先查看错误和差异，再确认导入。导入只保存草稿，
  不自动提交、不触发模型分析。供应商显式提交后接入原影响评估流程。
- 项目与角色：管理员创建账号、项目、授权并管理启停与密码重置；项目负责人
  分派经办人与评审人。经办人维护资料，评审人审批，负责人负责下发与最终确认，
  只读成员可查阅。管理员权限本身不授予项目业务访问权，经办与评审相互隔离。

问卷答案与标签随已确认范围进入 PRD 模型输入。CSV 校验固定身份、表头、行键、
必填条件、有效期、操作账号和版本；旧预览不能覆盖后续保存。
