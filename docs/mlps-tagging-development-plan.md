# MLPS 标签驱动分类与评估：开发计划

日期：2026-10-25。状态：设计草案，供开发与控制库审核使用。

目标：初期问卷形成系统画像和 L1/L2/L3 内部分级；在 MLPS 两张工作表中为每条控制项增加标签及适用条件；系统依据已确认答案选择后续评估问题，并解释选择原因。控制库同时支持前端手动新增/修改、标准 Excel 模板批量新增/更新，以及后续其他来源的控制条目。

本文件保留设计目标。2026-10-25 已实现版本化控制库、前端手动维护、XLSX/MLPS 导入与标注导出、规则草稿审核发布、标签分类和评估衔接；实际接口与操作见 [控制库使用说明](control-library.md)。逐组件独立匹配尚未实现，当前使用系统级画像及混合部署选择。MLPS 映射仍需逐条业务审核；L1 子集由管理员明确配置，不自动发布。

## 4. L1/L2/L3 建议规则与控制方案

建议采用显式规则命中，不用标签数量计分。以下为待发布的内部政策草案，工作簿本身不提供这些分级阈值。

| 内部等级 | 建议触发条件 | 默认控制方案 |
|---|---|---|
| L3 关键 | 任一已确认条件：严重数据泄露/篡改后果、重大生产/资金/安全操作、严重不可逆业务影响、可接受中断小于 4 小时 | `MLPS3_REFERENCE`，以三级来源条目为主 |
| L2 重要 | 无 L3 命中，且涉及内部业务/个人数据、公网或合作方业务访问、多团队/客户依赖、缺乏可用替代，或中断容忍为 4 至不足 24 小时 | `MLPS2_REFERENCE` |
| L1 基础 | 必填风险问题已知，均低影响，权限有限且影响可恢复，中断容忍至少 24 小时，有可行替代 | `INTERNAL_BASIC`，从二级表人工审核的基础子集 |

规则细节：

- 恰好 4 小时映射 L2，恰好 24 小时映射 L1 的时间维度；其他高风险规则仍可提升等级。
- 公网静态公开内容、只出站上网、远程管理本身不自动判 L3。生产管理的影响范围通过 IAM-01 判断。
- 缺失或未知的风险必答项使建议至少为“暂定 L2 / 待确认”；已知 L3 命中保持 L3。仅缺失邮件等筛题事实不自动提升等级，但产生控制候选。
- 允许手工选择等级并填写原因；降低等级形成例外，保留原建议。手工分级不免除筛题事实，缺失事实进入候选。
- 管理员发布方案时审核等级规则、L1 子集和控制方案映射。页面明确显示当前采用的方案；未配置 L1 子集时禁止生成空的 L1 评估。
- 若用户指定已有 MLPS 二级/三级评估目标，记录该独立目标及来源，选择对应控制方案；内部等级不能悄然降低它。目标与建议有差异时展示复核项。
- 二级、三级原始条目独立保存。三级方案不直接将两表全部相加；通过人工审核的 `control_family_id` 关联相近条款，处理同义、增强、拆分、一对多和无对应条款。未经审核不自动去重或覆盖。

## 5. 标签机制：系统事实与控制适用性

系统答案生成事实，例如 `net.public_ingress=yes`。控制库记录“何种事实使此控制适用”，不把某个项目的答案回写成所有系统共用的属性。

| 对象 | 保存内容 | 示例 |
|---|---|---|
| 标签定义 | 稳定 code、中英文名称、类型、值域、解释、版本 | `ops.remote_admin`，枚举 yes/no/unknown |
| 问卷问题 | 稳定 ID、选项、显示条件、映射规则 | OPS-01=yes → 远程管理标签 yes |
| 系统画像 | 标签值、组件、问题/答案引用、确认人和时间、修订号 | `OPS-01` 答案产生 `ops.remote_admin=yes` |
| 控制主题标签 | 描述控制覆盖主题，供检索与解释 | `network_boundary`、`remote_management` |
| 控制适用规则 | 无条件或结构化 all/any/eq/in 条件 | `ops.remote_admin == yes` |
| 匹配决定 | 结果、命中规则、事实来源、责任人、覆盖/排除原因 | 适用：OPS-01 选择了远程管理 |

`net.public_ingress` 是“系统是否可被公网访问”；控制上的“公网访问相关”是相关性标记。普通边界规则可以与公网相关，但也适用于内部网络。两者不能作为同一个布尔字段使用。

条件表达式使用受限 JSON，禁止执行字符串代码。首版支持 `all`、`any`、`eq`、`in` 与字面量 true；约束嵌套深度、节点数和字典引用。等级规则可单独支持数值比较，适用性规则先保持简单。

三值逻辑：all 中有 false 则 false，全部 true 则 true，否则 unknown；any 中有 true 则 true，全部 false 则 false，否则 unknown。缺失值为 unknown，不能把 `unknown != yes` 当成 no。

- true → 适用，进入评估；通用基线规则直接为 true。
- false → 不适用建议，保留条款和原因供查看/人工恢复。
- unknown → 待确认候选，展示缺失问题；确认控制集前逐项处理。
- 尚未审核的控制规则不能因空值被当作无条件规则或自动排除；发布时要求显式模式与已审核状态。
- 云和外包改变责任主体及证据来源；设施、网络等控制可以要求供应商提供证据，不因“不是自有机房”整体消失。

## 6. 工作簿新增列

实施时输出一个带标签的新版本工作簿，保留原始两表 A–J、原文、中英文、原始风险标记和顺序。每张表从 K 列开始追加以下列。原文件作为来源保留；所有新增内容注明草案或审核状态。

| 列 | 字段 | 内容 |
|---|---|---|
| K | `control_id` | 如 `MLPS2-7.1.4.1-c`；导入检测规范化后的重复编号 |
| L | `source_level` | 按明确工作表映射填写 2 或 3 |
| M | `control_family_id` | 经审核的跨等级控制族；未审核可空 |
| N | `assessment_profiles` | 内部基础、二级参考、三级参考的适用方案集合 |
| O | `topic_tags` | 主题代码，管道符分隔；不隐含 AND 匹配 |
| P | `public_access_relevance` | 公网相关 / 非公网专属 / 待审核；用于可读筛选，不直接决定排除 |
| Q | `question_ids` | 影响适用性的分类题 ID |
| R | `applicability_mode` | `always` 或 `conditional` |
| S | `applicability_rule` | 确定性的 JSON 条件表达式；always 填 true |
| T | `rule_description_zh` | 人可读条件和边界说明 |
| U | `rule_description_en` | 同义英文说明 |
| V | `responsibility_rule` | 客户 / 供应商 / 共享 / 按组件，及对应配置代码 |
| W | `tagging_basis` | 原始条款定位和映射理由；区分直接条件与人工推导 |
| X | `review_status` | draft / reviewed |
| Y | `rule_version` | 标签与映射版本 |

新增一个“标签字典与说明”工作表解释代码、枚举、问题和规则语义。需要项目答案导出时另行导出系统画像/评估结果，保持控制目录作为可复用模板。

标注流程：提取条目 → 按条款、对象、实施方法生成候选映射 → 逐条审核 346 条 → 检查条件过窄和未知值 → 导出工作簿 → 导入预览 → 原子发布。自动关键词/模型只生成可解释草案；正式匹配由已审核规则完成。

## 7. 真实条款映射示例

下表是建议规则示例，实施时需结合条款的评估对象和实施方法逐条审核。

| 来源条目 | 建议规则 | 预期行为 |
|---|---|---|
| 二级行 21，7.1.3.1(a)；三级行 32，8.1.3.1(a) | 公网入口、互联网出站、合作方互联、内部跨区任一 yes；再结合边界对象清单 | 无公网但跨内网区域仍进入边界评估 |
| 二级行 34，7.1.4.1(c)；三级行 54，8.1.4.1(c) | `ops.remote_admin == yes` | 内网远程管理同样要求鉴别信息传输保护 |
| 二级行 53–54；三级行 84–85，个人信息保护 | `data.personal == yes` | yes 纳入；unknown 候选；明确 no 给出不适用建议 |
| 三级行 50，8.1.3.5(d) | 远程访问行为或互联网访问行为存在 | 不把“公众访问本系统”与“系统用户访问互联网”混同；必要时补充远程业务访问明细 |
| 三级行 46，8.1.3.4(b) | `app.mail_processing == yes` | 选择邮件场景后纳入垃圾邮件检查 |
| 二级行 90–91；三级行 141–147，自行软件开发 | `delivery.models` 含 in_house | 内部开发对应检查；混合模式可同时命中外包开发 |
| 二级行 135–136；三级行 209–212，外包运维 | `ops.outsourced == yes` | 纳入协议、能力、责任检查 |
| 三级行 34，8.1.3.1(c)，防止私自外联 | 按内部网络边界对象适用，不能仅要求 `net.internet_egress=yes` | 宣称“不允许上网”的系统仍需检查防止违规上网 |

公网案例：用户选择“公网业务入口=yes、远程管理=yes、个人信息=yes”，系统生成三组事实，内部等级至少 L2（如有高影响条件则 L3）。在对应方案下纳入边界、访问控制、攻击防护、远程认证及个人信息条款。后续问题说明“由 NET-01/OPS-01/DATA-01 触发”，并链接到原条款。

改成“公网入口=no、内部跨区=yes、远程管理=yes”后，内部边界和远程管理问题仍保留。只有适用规则明确限定公网场景的子问题才移出，不删除通用身份、日志、备份、漏洞与管理制度控制。

| 问卷 | `backend/app/intake/questionnaire.py`、`assessment.py`、`service.py` | 新问卷、条件显示、确认事实、数值单位、来源和版本；统一 facts 映射 |
| 分级与匹配 | `backend/app/domain.py`、新增纯函数匹配模块 | 独立内部等级和控制来源；三值规则求值及可解释结果 |
| 目录导入与维护 | `backend/app/catalog.py`、新增工作簿解析和目录草稿模块 | MLPS 来源适配、标准模板、手动新增/修改、可扩展域字典、条件校验、双语及原文、source_ref 持久化、全量预览及发布 |
| 数据层 | `backend/app/db.py`、`backend/migrations/` | 增量增加控制规则和来源、方案版本、画像修订、匹配快照；旧快照按旧版本读取 |
| 工作流 | `backend/app/service.py`、`integration.py` | 确认后匹配、重算差异、人工决定保留与复核、PRD及基线失效控制 |
| 前端 | `Questionnaire.tsx`、`discovery.tsx`、`BriefReview.tsx`、`brief.ts`、`i18n.tsx`；新增控制库管理页面 | 动态问卷、等级理由、标签预览、控制适用状态、来源链接、中英文文案；控制编辑器、条件构建器、模板下载、上传预览和版本差异 |
| 文档 | README、implementation、development-specification、导入说明 | 更新新方案及流程，明确历史规则停用状态 |

存储可复用现有 Questionnaire JSON 快照，但新增 `schema_version`、`mapping_version`、`scheme_version`、已确认 profile 及内容哈希。已发布控制保存 `source_file_hash/sheet/row/clause/subitem`、原文、条件、责任规则、审核元数据。不能只存 Excel 路径，文件移动后仍需可追溯。

系统事实以确认的问卷/画像为唯一权威来源；Context 的标签视图从该修订生成。模型提取只作为建议，必须经用户确认，不直接改等级或匹配结果。旧 `external_access` 无法区分出入站时保留未知并要求补答。

建议新增分类预览、匹配预览接口，复用现有问卷保存/提交和分类确认命令。所有写入沿用组织/项目权限、版本冲突 409、幂等键、同事务审计。预览返回各条的 status、rule_id、answer_refs、source_refs、responsible_party、reason。

每次确认固定 questionnaire/profile/规则/目录/控制选择的版本与 hash。事实变更后重新计算全部控制：旧的自动命中可能失效，不能只添加新项；人工加项/排除保留为待复核决定。下游 PRD、供应商轮次、报告和双方确认按现有修订链失效，历史记录保留。

### 8.1 前端控制库维护入口

导航中设置长期可用的“控制库 / Control Library”入口。列表支持按控制编号、标题、来源框架、安全域、适用方案、标签和状态检索。顶部提供“新增控制项”“下载 Excel 模板”“上传 Excel”“导出当前版本”；详情提供“编辑草稿”“复制为新条目”“查看历史”“停用”。

| 页面/功能 | 交互与结果 |
|---|---|
| 手动新增 | 填写编号、标题、要求、评估方法、对象、安全域、适用方案、必选属性、来源、责任规则；选择主题标签与适用条件；保存草稿 |
| 手动修改 | 打开现有条目，显示当前发布版与编辑版差异；保存带预期修订号的草稿；发布后形成新版本 |
| 适用条件构建器 | 选择“始终适用”或“满足以下条件”；以标签、运算符、值组成条件，支持“全部满足”和“任一组满足”；自动生成规则，无需用户编写 JSON |
| 条件试算 | 输入示例系统画像或选择有权限的系统快照，显示命中、未命中、待确认及原因；试算不改变实际评估 |
| 上传预览 | 按新增、更新、停用、无变化、错误、冲突分组；逐行显示差异、原值、新值和 Excel 单元格定位 |
| 发布 | 显示控制及规则变更摘要，校验完整草稿；显式发布一个不可变目录版本 |
| 评估内补充 | 控制复核页保留“新增项目控制项”；普通项目编辑者可在授权项目范围使用，经目录管理权限审核后才可收录组织控制库 |

表单至少要求一种语言的完整标题、要求和评估方法；另一种语言可补充，缺失时显示已提供原文。切换界面语言不自动翻译或覆盖用户录入内容。

### 8.2 可下载的标准 Excel 模板

新增控制使用独立的 `control-import-v1.xlsx` 模板，不要求用户复制 MLPS 原文件结构。第 6 节的 MLPS 加标签工作簿作为专门的来源适配格式；两种导入都转换成相同的内部控制草稿模型。

模板由服务器按用户所属组织的已发布字典生成，包含版本信息、字段说明、可选代码及 Excel 数据验证列表。服务端重新校验所有值，不能只依赖下拉框。用户可下载空白模板，也可导出当前目录用于批量修改。

| 工作表 | 用途和主要字段 |
|---|---|
| `Instructions` | 模板版本、目标目录、导出基准版本、使用说明；示例明确位于说明页，不作为导入控制 |
| `Controls` | 每行一条控制；字段见下表 |
| `Conditions` | 条件行：control_code、group_id、tag_code、operator、expected_value；同组 AND、组间 OR；与前端条件构建器同义 |
| `Dictionary` | 供查询的域、标签、枚举值、方案和责任规则代码及双语名称；修改本表不会创建服务器字典项 |

| Controls 字段 | 要求与语义 |
|---|---|
| `operation` | 必填 `create/update/retire`；禁止根据编号是否存在悄然改变操作类型 |
| `control_code` | 必填，组织目标目录内唯一；用户可读编号；修改已存在编号通过单独明确操作处理 |
| `control_id`, `expected_revision` | update/retire 必填，由导出提供；create 留空，服务器生成不可变 ID；校验 ID 与编号一致 |
| `title_zh/en`, `description_zh/en`, `verification_zh/en` | create/update 至少有一套完整语言内容；既有另一语言不应因漏列被清空 |
| `assessment_object`, `domain_code` | 评估对象和已配置安全域；create/update 必填 |
| `assessment_profiles`, `required` | 必填方案代码集合及 true/false；来源等级不自动替代适用方案 |
| `topic_tags` | 可选的已配置主题标签，管道符分隔；不隐含适用条件 |
| `applicability_mode` | create/update 必填 always/conditional；conditional 必须有 Conditions 行；always 不允许关联条件行 |
| `responsibility_rule` | 已配置责任规则代码；支持客户、供应商、共享及按组件分配 |
| `source_framework`, `source_version`, `source_ref` | 来源框架、版本、定位；支持 MLPS、其他标准、企业政策和用户自定义；自定义允许没有外部条款引用 |
| `source_level`, `control_family_id` | 可选；非 MLPS 来源可以没有来源等级；控制族关联须验证 |
| `change_reason` | update/retire 必填，create 可选；用于审计和差异解释 |
| `clear_fields` | 更新时显式清除可选字段的名称集合；禁止清除必填字段；不能与同字段非空值同时出现 |

批量更新采用明确的补丁语义：可选单元格为空表示保持原值，清除必须写入 `clear_fields`；必填列/值缺失报错。条件规则是一个整体：conditional 提供完整替换条件；切换为 always 必须显式填写模式并在预览中展示条件删除。上传文件未包含的原控制项保持不变，不能把增量上传当作全库覆盖。

首版规则编辑统一使用“组内 AND、组间 OR”的结构，覆盖本计划的主要场景。底层受限 JSON 可承载更深表达式，但首版发布校验要求能无损呈现和导出为该结构；不能让导出/导入或表单编辑静默改写规则。

导入步骤：选择目标目录和基准版本 → 上传 → 解析到临时导入批次 → 校验并预览 → 修正错误 → 合并为目录草稿 → 明确发布。存在任一无效行时不部分合并；预览后基准版本变化则返回冲突并重新预览，避免覆盖前端编辑。

校验需覆盖模板版本、重复编号、未知域/标签/方案、条件类型、规则引用、版本冲突、跨组织 ID 和过期字典。错误包含 sheet、row、column、code、message，并支持下载错误清单。仅接受 `.xlsx`；对上传/解压大小、行数设置上限，不执行公式、宏或外部链接，控制输入字段中发现公式则报错。标准模板与 MLPS 适配均保留来源定位。

### 8.3 数据与扩展边界

控制定义采用通用身份：服务器 `control_id` + 不可变 `control_revision_id`，另有可读 `control_code`。第 6 节示例 `MLPS2-7.1.4.1-c` 作为来源编号；导入时映射到通用身份，避免未来条目必须使用 MLPS 编码。已发布目录版本引用具体控制修订；修改创建后继修订，停用通过新目录版本体现。

新增组织级 `ControlDraft`、版本化标签/域/方案字典和导入批次记录。草稿删除与已发布条目停用分开；已被评估引用的控制修订始终可读取。组织目录与项目专属条目各有授权范围，发布权限不等于项目或供应商确认权限。

对后续扩展做以下约定：

- 新增使用现有标签和规则操作符的控制，只需前端或模板维护，无需修改代码。
- 域、主题标签、事实标签、选项和控制方案作为配置数据管理；增加新框架无需扩展固定 Python 枚举。
- 新的事实标签必须定义类型、值域和取值来源。需要用户回答时，在“分类问题与标签”管理页配置问题、选项映射和显示条件，并经过类型、引用与循环依赖校验。自由填写的主题标签不能自动变成系统事实。
- 问卷/字典/规则版本作为兼容配置一起发布；新增问题不自动补写旧答案。已有系统升级时显示待补充项，缺失事实按 unknown 处理。
- 增加标签本身不改变 L1/L2/L3 判级；如需影响判级，单独修改并发布等级规则。
- 新运算符、新题型或外部系统取值接口需要受控代码扩展和回归测试；普通配置不能执行脚本。
- 已有评估固定目录版本；用户选择“升级控制库版本”后查看差异并建立新评估修订，重新复核相关成果。

### 8.4 建议接口与一致性

以下为新增/扩展接口建议，正式实现时与现有路由合并，避免双套维护路径：

| 接口 | 用途 |
|---|---|
| `GET /api/v1/control-template?catalog_id=...` | 下载标准模板及当前可选字典 |
| `GET /api/v1/catalogs/{id}/export` | 导出带 control_id、expected_revision 的指定目录版本 |
| `POST /api/v1/catalogs/{id}/draft-controls` | 手动创建控制草稿 |
| `PATCH /api/v1/control-drafts/{id}` | 修改带乐观锁版本的草稿 |
| `POST /api/v1/control-drafts/{id}/preview` | 试算规则、显示修改差异 |
| `POST /api/v1/catalog-imports` | 扩展现有导入接口，识别标准 XLSX、MLPS 适配及既有 CSV |
| `POST /api/v1/catalog-imports/{id}/apply` | 将已校验批次原子合并到指定目录草稿 |
| `POST /api/v1/catalogs/{id}/publish` | 手动编辑与批量导入共用的目录发布命令 |
| `POST /api/v1/systems/{id}/catalog-upgrade-preview` | 展示升级对控制、问题及成果的影响 |

既有导入 publish 接口可作为兼容入口，内部调用同一发布服务。手工表单、Excel 和 CSV 共用字段校验、规则求值、组织权限、幂等及审计；不得出现手工能保存而模板不能无损导出或导入的控制。

## 9. 验收与发布条件

离线确定性案例放入 `evals/deterministic/`；使用隔离临时数据库和模拟模型响应。

1. 两表分别识别 135/211 条；不同 J 列头正确处理；稀疏 System Level 不导致丢行；原始值、中英文和 source_ref 完整。
2. 同条款不同子项不冲突；重复稳定 ID 报错；双表相近条款未经审核不合并。
3. 公网业务=yes 纳入对应控制；仅出站=yes 不推导公网入口=yes；公网=no、跨区=yes 保留边界控制。
4. 公网=no、远程管理=yes 保留远程鉴别保护；不允许外联仍保留违规外联防护。
5. 个人信息=yes/no/unknown 分别进入适用/不适用建议/待确认；缺失标签等同 unknown。
6. any(true,unknown)=true；any(false,unknown)=unknown；all(false,unknown)=false；错误操作符、未知代码和过深表达式拒绝发布。
7. 无备份、无防火墙等实施缺口不使控制不适用；云/SaaS 责任转给供应商时保留证据任务。
8. L3 单项高影响不能被低风险回答抵消；4/24 小时边界准确；未知风险项不成为确定 L1；普通适用性未知不会被错误解释成高风险。
9. L1 未配置控制集不能生成空评估；内部等级与指定来源方案独立保存；三级方案避免未经审核的二三级叠加重复。
10. 修改答案后重算新增和退出项，保留人工决定待复核；旧 PRD、报告和双方确认不得用于新基线。
11. 并发修改拒绝旧版本；跨组织、未授权供应商访问被拒绝；失败导入不留下半发布目录。
12. 相同版本相同内容幂等；相同版本不同内容冲突；旧评估继续固定旧目录；新规则发布不自动改写历史结果。
13. 中英文切换不改变自填答案、来源文字和证据；规则草案与模型建议均明确标识。
14. 完整旅程最终仍要求客户与供应商独立确认同一基线 hash。
15. 用户手动新增一个非 MLPS 控制，选择已有标签，发布后新评估可命中；无需代码修改；项目专属条目不能泄漏至其他项目。
16. 标准模板批量新增、更新、停用分别有效；漏行不删除；更新编号与 ID 不一致、重复操作、过期 revision 报错；任一错误不部分合并。
17. 导出→编辑→导入保持文本、双语、标签和规则语义；可选空值保持原值，clear_fields 明确清除；always/conditional 切换可解释。
18. 上传预览期间另一个用户修改草稿或发布目录，提交返回冲突；手工与上传共用版本和校验，不能互相静默覆盖。
19. 新标签与问题发布后新系统可回答；旧系统升级时补答或保持 unknown；删除被引用标签、配置循环条件、错误类型和不兼容版本被拒绝。
20. 控制修改/停用后历史评估与基线仍能读取原始修订；显式目录升级才影响当前评估，并按修订策略重新确认。
21. 错误模板版本、公式输入、超限文件、跨组织 ID 和篡改字典被拒绝；错误可定位至具体工作表和单元格。
