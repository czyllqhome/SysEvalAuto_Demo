# 系统初步分级与框架选择（SYS-SCREEN/2）

这是内部评估优先级和控制范围初筛，不是法定等保定级结论。参考 GB/T 22240—2020 的“受侵害客体 × 损害程度”分析，分别询问业务信息受损、系统服务中断，采用最高触发等级，不平均抵消。正式定级可能涉及四、五级；本应用 L1/L2/L3 不能代替该过程。

标准资料：[国家标准公开信息](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=63B89FFF7CC97EBBBED8A403396F0F00)、[工信部《信息安全等级保护管理办法》](https://www.miit.gov.cn/jgsj/xxjsfzs/xxgk/art/2020/art_a981907528694176a61b5b52c2d19895.html)。下述人数和中断门槛为本应用设计的内部规则，不是以上标准规定的人数定级门槛。

## 核心问题

- 个人信息去重人数：无、少于 1 万、1 万至不足 10 万、10 万至不足 100 万、100 万及以上、未知。
- 敏感个人信息去重人数：无、少于 1 千、1 千至不足 1 万、1 万至不足 10 万、10 万及以上、未知。敏感个人信息是个人信息的子集，矛盾数量拒绝保存。
- 商业秘密或其他非个人敏感业务信息，与敏感个人信息数量分开记录。
- 公网入口（认证或白名单入口也算），与主动访问互联网区分。
- 部署方式（自有、供应商机房、云、SaaS）及是否公有云；用于责任和适用性，不单独升等。
- 分别判断数据泄露/篡改与服务中断影响谁：个人/企业等合法权益、公共利益/社会秩序、国家安全；损害一般、严重、特别严重。
- 业务中断影响、最长可接受中断时间、可行的人工替代流程。
- 系统交互：无、只读、写入或交易、关键生产/核心系统控制。
- 其他适用性标签可展开补充；未知标签不会被当成“否”。

## 决策规则

| 条件 | 内部初筛最低等级 |
| --- | --- |
| 合法权益的一般损害、低影响，无其他触发且核心问题已回答 | L1 |
| 合法权益严重/特别严重损害；公共利益一般损害 | L2 |
| 公共利益严重损害 | L3 |
| 国家安全相关或公共利益特别严重损害 | L3 优先级并标记专家复核，不能理解为正式三级 |
| 个人信息人数 1–99,999 | L2 |
| 个人信息人数 ≥100,000 | L3 |
| 敏感个人信息人数 1–999 | L2 |
| 敏感个人信息人数 ≥1,000 | L3 |
| 商业秘密等敏感业务信息、公网入口、写入其他系统、无人工替代 | L2 |
| 严重业务中断或控制关键生产/核心系统 | L3 |
| 容忍中断低于 240 分钟且无人工替代 | L3 |
| 容忍中断低于 1,440 分钟，未满足上一项 | L2 |
| 关键答案未知 | 至少暂定 L2，保留全部未知问题 |

中断门槛复用所用配置的 critical_minutes / important_minutes（默认 240 / 1440）。人工调整必须填写原因；降低等级保留例外记录。人工替代不会抵消已触发的严重影响。

## 与控制库解耦及框架匹配

初筛问卷在空控制库时也可填写、预览和确认。默认提供 MLPS，其他框架从组织草稿或已发布控制项的 source_framework 获取。支持多选；不把未选择框架的条目自动纳入。

匹配顺序为：所选来源框架 → 对应等级的 assessment_profiles → 条目适用条件。未指定 MLPS 目标时按内部等级选择方案；已有明确 MLPS 二/三级目标时使用该目标等级的方案，并保留与内部等级的差异提示。默认 L1=INTERNAL_BASIC，L2=MLPS2_REFERENCE，L3=MLPS3_REFERENCE；自定义框架条目也需显式关联相应等级方案。来源二级/三级不会隐式继承为其他等级。

框架/等级缺少已发布条目时 controls_ready=false，允许保存初筛，但应用说明确认与控制匹配被阻止，避免以空控制集声称完成评估。发布后可“加载最新控制库”，预览并重新确认；不能自动改变已确认评估。旧 MLPS-TAGS/1 评估继续使用旧配置路径，避免静默改变历史结论。

## 实现及追溯

接口为 GET/PUT `/api/v1/systems/{id}/screening`、POST `/screening/preview`。分类确认沿用 `/classification-confirmations`，scheme=SYS-SCREEN/2。确认保存事实、触发依据、未知项、专家标记、框架、控制版本、方法配置快照及摘要。修改已确认画像使下游成果失效，已有历史记录保留。原始描述中的模型推断不能自动替代问卷答案。

系统名称来自创建评估时的 name 字段，不从描述自动改写。初期阶段可通过“修改名称”编辑，保留权限、修订号及前后名称审计。


## 初筛页面交互

“分级方式”位于问卷顶部，先选择按回答推荐或人工调整；选择人工调整后，
采用等级与调整原因在同一区域显示。切换方式保留已填写的事实、等级和原因。

“补充控制适用条件”用于展开非核心事实，例如公网管理入口、远程管理、外网互联、
重要数据存储/传输、用户/程序账号、外包运维、软件交付方式和客户/供应商各层责任。
这些事实主要用于控制适用性与责任匹配；SYS-SCREEN/2 的初筛触发规则仍以本节前述
核心问题为准。开启后，问题加入上方四个分类；关闭只隐藏问题，保留已填写答案。
未回答按待确认处理，不能把未回答当作不适用；补充事实也继续接受一致性检查。


## 应用说明确认的前置条件

控制审查阶段会集中展示导致候选控制适用性未知的问题，并标注必填及受影响控制编号。经办人可直接补充答案，点击“保存答案并更新匹配”；也可逐条明确纳入或排除并说明理由。补充使用评估已锁定的控制库与方法版本，不自动切换到新发布版本。涉及分级依据或与已确认应用说明冲突的答案须返回确认等级。

保存补充答案产生新评估修订并保留历史。未受影响的人工决定保持原样；受新答案影响的人工决定重新进入待复核状态。所有候选完成作答匹配或人工决定后，才能生成 PRD。

应用说明页在 SYS-SCREEN/2 的已确认分类尚未 controls_ready 时，提前显示阻塞提示与
管理员发布、经办人重新确认分类的操作路径，并禁用“确认说明并匹配控制”。草稿仍可编辑保存。
管理员可点击“一键发布”直接发布有效草稿，也可逐项审核后发布；经办人保存说明，返回分类页保存初筛草稿，
加载最新控制库、预览并重新确认，然后返回说明页。仅发布控制库不会自动改变评估的分类快照。

本页逐项标记必填：目标摘要、范围与不做事项、至少一个功能且每个功能名称非空、涉及部门、
使用和审批角色、业务责任角色，以及核对确认复选框。空值在字段旁提示。功能说明、业务流程、
数据说明、集成与交付约束目前允许为空；待澄清事项可保留进入 PRD。必填检查通过和控制库就绪
是独立条件，控制库未就绪不表示本页漏填。中英文界面均提供说明与必填标记。

### 初筛页面分区

分级方式与采用等级、系统情况分别显示标题。初筛规则与数量门槛位于页面上方的折叠参考区。补充控制适用条件在独立区域展开，问号支持鼠标悬停及键盘聚焦说明；收起保留答案，基础问题与补充问题共享原有事实及条件显隐规则，不改变分级或控制匹配逻辑。

初筛表单字段标题（含提示时为提示末尾）到输入控件统一为 8px；分级方式、采用等级和调整原因按顶部对齐。

调整原因文本框默认高度与同排下拉框一致（44px），保留纵向拖动扩展以填写长文本。


初筛规则与数量门槛按问题展示：数据与权限下的人数、影响对象、损害程度等
问题旁使用圆圈感叹号，悬停或键盘聚焦显示对应说明，Escape 可收起。
网络部署与业务影响规则也跟随对应问题展示，不再占用顶部独立说明区。
提示保留内部初筛与正式定级的区别，时间门槛使用当前配置值；不改变分级算法。
